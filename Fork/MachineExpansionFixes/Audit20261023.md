# MRE Code Audit — 2026-10-23

## Scope and evidence

Reviewed the effective MRE script tree at upstream commit `e9d54b14a1f22730f17709efb23b37d83361c2a6`, with existing fixes applied: 551 `.txt` files under `common` and `events`, containing 411 event definitions. Indexed event calls, on-action event references, inline-script paths, custom object references, scripted-effect arguments, duplicate event conditions, scripted-function recursion, and constant references. Followed candidate issues through their callers and definitions before making corrections.

Current installed Stellaris source was used for API and constant comparisons, including:

- `common/component_templates/00_utilities_shields.txt` and `common/scripted_variables/02_scripted_variables_component_cost.txt`.
- `common/ascension_perks/00_ascension_perks.txt` and `common/inline_scripts/technologies/rare_technologies_weight_modifiers.txt`.
- `common/script_values/00_script_values.txt`, which documents numerical operations and `complex_trigger_modifier.parameters`.
- `common/scripted_effects/biogenesis_effects.txt`, whose largest-pop-group selection matches the existing MRE ordering. That ordering was checked and retained.

This is a source audit, not proof that every gameplay path works. No game launch or automated tests were run. Graphics, translations, all combinations of other Workshop mods, and every generated editor interaction were not exhaustively exercised.

## Candidates requiring further investigation

- **Core-fabrication stop/start timer:** the old watcher is delayed while a restart creates another delayed watcher. If both survive until production is active again, parallel advancement may be possible. A correction needs reliable event-loop ownership/cancellation and an in-game reproduction; changing the active flag alone is insufficient.
- **Army refill interrupted by occupation/ownership changes:** event `.2001` has an occupation pre-trigger and a persistent refill flag. The timer may stop with that flag still set. Safe recovery must account for queued events and conquest/recapture before changing the restart logic.
- **AI Splitting remains disabled:** correcting `root.ruler` does not validate the old assumption that a new leader starts at level one, or the interaction with modern starting-level bonuses. This audit does not enable it.
- **Dormant/generated compatibility helpers:** ten unresolved custom object aliases point to removed or undeployed features; one unused commander Maniacal helper refers to a missing helper and contradictory class conditions. No active caller was found for these aliases in the shipped tree. Do not guess replacement technology IDs or enable the undeployed features.
- **Reactor-tech core production scaling:** the reactor-level variable is recorded for display but is not wired into production. Connecting it would choose a new production rule and belongs to authored balance design.

## Findings deliberately ruled out

- Script values support `mult`, `factor`, and `multiply`; the `multiply = 0.2` helper is valid syntax.
- The existing `ordered_owned_pop_group` selection at position zero matches vanilla's documented-in-source largest-group pattern. No inverse ordering was added.
- The raw first-pass civic-reference warnings came from civics being nested under `common/governments/civics`; indexing that directory resolves them. They were not gameplay bugs.
- Template constants such as `@b$TIER$...` are assembled by inline-script parameters and were not replaced with guessed values.

## Package boundaries

All corrections are in MachineExpansionFixes. MRE's upstream checkout stays unchanged. No new tradition effects, core districts, fabricator-limit changes, food replacement, or authored upkeep curve were implemented by this audit.
